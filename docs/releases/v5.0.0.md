# CPU-LLM v5.0.0 (stable)

Released 2026-10-29 from `release/v5`. v4 (`/v4`) is the previous stable; v1,
v2 and v3 are archived but still served.

## What is new

Feature page: [docs/versions/v5/features.md](../versions/v5/features.md).
Operations guide: [docs/OPERATIONS.md](../OPERATIONS.md).

- **API keys with roles** (viewer / engineer / admin): `GET/POST
  /api/admin/keys`, `DELETE /api/admin/keys/{id}`; keys hashed at rest, shown
  once, last-used tracked; `Authorization: Bearer cpk_…` on dashboard and
  (admin role) admin endpoints; audit actor `key:<name>`.
- **Require an API key** (`access.requireKey`): dashboard API refuses
  anonymous callers; health, metrics and agents unaffected.
- **Backup and restore:** `GET /api/admin/backup` (gzip JSON bundle v1 with
  settings, agents, campaigns, audit, jobs with reports and bundles),
  `POST /api/admin/restore` (`{ bundle }` or `{ gzip_b64 }`) writes the files
  and restarts the process. Admin cards for both.
- **Hardening:** security headers on every response, HSTS over TLS.
- Admin → API keys and Backup cards; public config carries the access mode.

## Tests

Server 28 (adds keys/roles/requireKey/headers and a backup → restore
round-trip into a fresh install), frontend 28, agent 3 + pipeline.

## Upgrade notes

- No new environment variables. Existing installs keep open access until an
  admin turns **Require an API key** on.
- Restore exits the process with code 0 on purpose; make sure the supervisor
  restarts it (Hostinger, systemd `Restart=on-failure` → use `Restart=always`).
- v6 preview at `/v6` (OIDC, retention policies, Fleet tab, webhooks, CLI).
