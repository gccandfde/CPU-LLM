# CPU-LLM v4.0.0 (stable)

Released 2026-10-29 from `release/v4`. v3 (`/v3`) is the previous stable; v1
and v2 are archived but still served.

## What is new

Feature page: [docs/versions/v4/features.md](../versions/v4/features.md)
(served at `/v4/features/`).

- **Benchmark suite** (`cpullm/suite.py`, job kind `benchmark`): STREAM
  copy/scale/add/triad, GEMM TFLOPS by size and dtype, SDPA attention decode
  and prefill at several contexts, embedding gather; CPU and CUDA/ROCm from
  the same agent. **Benchmarks** tab: run (quick / standard / large, device
  selector), recent runs, compare-machines table.
- **Power optimiser** (`cpullm/power.py`, job kind `power`): affinity-based
  active-core sweep (Linux, Windows, containers), RAPL package energy via
  powercap when readable, estimated watts labelled as such otherwise,
  optional `sysfs` core offlining and cpufreq governor on Linux hosts with
  permission (restored afterwards), recommendations for performance /
  balanced / efficiency. **Power** tab: run, recent runs, curves and table.
  Telemetry carries `power_w` on hosts with RAPL.
- **Runs:** detail pages for the new kinds, reports and JSON bundles, run
  summaries in lists and CSV; Overview/Compare/Recipes ignore non-tuning
  runs where tuning fields are needed.
- **API:** `POST /api/jobs` with `kind`; validation per kind; OpenAPI updated.

## Tests

Server 26 (adds kinds), frontend 28, agent 3 new (suite kernels, optimiser
sweep with affinity restored, estimate linearity) on top of the pipeline
tests. Benchmarks, Power and run pages checked at desktop and phone width.

## Upgrade notes

- Agents need the v4 agent for the new kinds (re-run the one-line installer;
  it keeps the name). Older agents fail such jobs with a clear error.
- Power measurements on Windows/VMs are estimates; use a Linux host with
  readable `/sys/class/powercap/intel-rapl*` for measured watts.
- v5 preview at `/v5` (plan: roles and API keys, SSO, backup/restore).
