# CPU-LLM v6.0.0 (stable)

Released 2026-10-31 from `release/v6`. v5 (`/v5`) is the previous stable; v1
to v4 are archived but still served. v7 (`/v7`) is the preview.

## What is new

Feature page: [docs/versions/v6/features.md](../versions/v6/features.md).
GPU guide: [docs/GPU.md](../GPU.md).

- **GPU everywhere.** Agent module `cpullm/gpu.py` (nvidia-smi inventory,
  1 Hz samples, power limits, a board-power meter); `hardware.gpus()` lists
  GPUs the driver sees even when PyTorch is the CPU build
  (`torch_visible: false`); telemetry carries `gpu_percent`,
  `gpu_mem_used_gb`, `gpu_power_w`, `gpu_temp_c` and a per-GPU list;
  `power.optimize()` dispatches on `device` to a GPU power-limit sweep
  (`power_limits[]`, `gpu_index`, `control: power_limit|none`, restores the
  original limit).
- **Dashboard:** Overview opens with *What this solves* and a *GPUs in the
  fleet* KPI; Machines shows driver, power limits and usability per GPU with
  the reinstall hint; live telemetry adds GPU utilisation, VRAM and board
  power panels with forecasts; Tune, Benchmarks (plus *Run on CPU and GPU*),
  Power (GPU mode) and Campaigns take the GPU as a device; power results
  render by power limit on GPUs.
- **Installer:** `CPULLM_DEVICE=cpu|cuda` on both installers; Linux/WSL
  default to the CUDA build when `nvidia-smi` is present and upgrade a
  CPU-only torch when CUDA is requested; Windows prints a hint and opts in.
- **Server:** `power_limits` and `gpu_index` validated on power jobs; power
  summaries carry `device`; `cpullm_agent_gpus` gauge; `/metrics` fixed for
  benchmark and power runs; OpenAPI documents job kinds.
- **Docs:** `docs/GPU.md` served at `/docs/gpu/`; Guide step *Use the GPU
  too*; roadmap moved to v6 = GPU, v7 = SSO, retention, fleet, webhooks, CLI.

## Tests

Server 28 (kinds test now covers GPU power validation, summaries and
`/metrics`), frontend 28, agent 9 (new `test_gpu.py`: nvidia-smi parsing,
aggregation, dispatch without a GPU, default power limits) + pipeline.

## Upgrade notes

- Agents upgrade by re-running the one-line installer. On Linux/WSL hosts
  with `nvidia-smi` the CUDA build of PyTorch is installed (a few GB); set
  `CPULLM_DEVICE=cpu` to keep the CPU build.
- No settings or data migration. Older agents keep working; they simply do
  not report GPU telemetry.
