# CPU-LLM v1.0.0 (stable)

Released 2026-10-29. First stable version: deployed at cpullm.gccandfde.com
from `main`.

## What is in it

**Dashboard tabs:** Overview, Machines, Tune, Runs, Recipes, Compare,
Architecture Lab and, new in this release, **Admin**.

**Agent** (Python, runs on the machine being tuned): hardware profile,
precision/quantisation/pruning/thread sweeps on CPU or CUDA/ROCm GPU,
accuracy budgets, operator trace, batch scaling, roofline, portable recipe
bundle and `cpullm.reproduce`.

### New: Admin tab

All server settings are controlled from the dashboard instead of environment
variables (details in [ADMIN.md](../ADMIN.md)):

- Dashboard login on/off and its password, separate admin password
- Agent token: show, copy, rotate; ready-to-paste start command
- Accept or refuse new machines; remove machines
- Offline timeout and live telemetry history
- Tuning: model list and default, custom models on/off, allowed precisions
  and devices, per-run limits, presets
- Data retention for finished runs
- Site title and tagline

Settings are stored in `DATA_DIR/settings.json` and apply without a restart.
Environment variables now only seed a fresh install; `ADMIN_PASSWORD_RESET`
recovers a lost admin password.

### Also in this release

- Agent on Windows/macOS detects the CPU name and ISA flags (AVX-512, VNNI)
  through `py-cpuinfo`.
- Docs for Windows Smart App Control (use the CPU PyTorch build there; GPUs
  via WSL 2).

## Upgrade notes

- Set `ADMIN_PASSWORD` before deploying, or the Admin tab cannot be used.
- An existing `AGENT_TOKEN` is kept, so connected agents keep working.
- If `DASHBOARD_PASSWORD` was set on a server without a settings file, login
  starts on with that password.

## Known limitations

- One job at a time per machine; runs are started one machine at a time.
- Single admin password (no per-user accounts yet).
- On Windows, `avx512_bf16` and AMX show as absent (py-cpuinfo cannot read them).
- Settings and runs are stored in files: fine for one server process.
