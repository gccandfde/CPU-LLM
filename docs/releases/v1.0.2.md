# CPU-LLM v1.0.2 (stable)

Released 2026-10-29. Fix release on `release/v1`.

## Turning a machine on is now one line

Users could not work out how to "turn on" a machine: it meant installing
Python and PyTorch, cloning the repository and running a command. Now:

- The site serves one-line installers at `/install/agent.ps1` (Windows) and
  `/install/agent.sh` (Linux, macOS, WSL). They download the agent from the
  site, set up Python with CPU PyTorch (CUDA build on Linux when an NVIDIA
  GPU is present), register the agent as a background service that starts at
  every logon/boot, and start it.
- **Machines → Add a machine**, **Overview**, the **Tune** tab's offline notice
  and **Admin → Agents** all show that line with the server filled in. When
  you are signed in as admin the token is filled in too; otherwise a
  placeholder and a link to sign in.
- Windows / Linux switch, Copy button, step-by-step notes, and a remove
  command.
- Options: `CPULLM_NO_SERVICE=1` (run until logout, no autostart),
  `CPULLM_UNINSTALL=1` (remove), `CPULLM_NAME` (machine name).

## Fixes

- Admin: the long agent command widened the page; it wraps now.
- Installer scripts never contain the token; it is pasted as an environment
  variable, so it stays out of web logs.

## Notes

- `scripts/build-site.mjs` now packages the stable agent as
  `site/install/agent.zip`; deployments must be built with it.
- Windows with Smart App Control blocks the CUDA PyTorch build: the Windows
  installer uses the CPU build; GPU agents run under WSL 2 with the Linux line.
